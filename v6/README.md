# 367 双臂遥操 V6

机器人桌面入口为 **V6遥操测试-367**。打开后，头显使用机器人地址的 HTTPS 8448 端口。网页使能会请求原厂全身复位，复位完成后，握住对应手柄 Grip 建立该手的实测起点。松开 Grip 保持当前位置。快速复位收回双臂，网页停用或关闭终端释放控制权。启动实机桌面时，如原厂 flow-service 正在运行，启动器会按平台约定暂停它，退出并确认交接后恢复。

## 如何读代码

- `teleop_v6/mapping.py` 把左右手置于同一操作朝向下，每只手从自己的末端实测位置接管。使用逐帧位移，抵达工作空间边界后向内移动即可退回。默认腕部旋转增益为 1。
- `teleop_v6/session.py` 管理一个正在求解的目标和一个等待中的最新目标。握持状态、复位和控制会话的变化使上一代结果失效。
- `teleop_v6/dexterity.py` 根据接近伸直时的外伸需求调节腕部姿态权重。原厂模型、关节限制、碰撞约束和单一关节输出端用于执行。
- `teleop_v6/elbow_reach.py` 用原生模型的肘轴、肩和腕中心反算目标腕距所需的屈肘角，和末端位姿、肘向一起进入同一有界求解器。手腕姿态变化会同步更新工具到腕中心的偏移。
- `teleop_v6/arm_shape.py` 从本机复位关节姿态建立每侧的肘弯方向。握持只重置手柄和伺服起点。头显提供肩、肘、腕骨架时，IK 在同一个求解周期内跟踪手柄位姿和人体肘部旋转方向。网页状态会显示「人体肘向」或「中立臂形」。肩肘腕接近一直线、遮挡或没有身体跟踪权限时，系统平滑回到中立参考。头显骨架可能包含设备估计值。
- `teleop_v6/controller.py` 和 `lifecycle.py` 管理使能及交接。已发出的全身复位继续等到底层反馈稳定。退出确认和新的使能依次执行，退出等待期间再次停用可取消排队的进入。
- `build.py` 在安装阶段从已核对指纹的 367 V5 运行库生成私有 ROS 适配层。改算法主要看上述模块。升级底层 V5 时需重新核对适配器及配置并运行仿真。
- `teleop_v6/bringup.launch.py` 连接 WebXR、映射、控制器。V6 接口统一在 `/teleop_v6/` 下。桌面上的 V5 和 V6 使用不同网页端口，共用机器人的关节控制锁。

## 仿真复测

在 367 上，从本目录运行 `bash run_v6.sh --simulate`。默认使用平台现有的 ROS Jazzy 和 Mink 运行环境。输出目录在启动时打印。

1. `test_boundaries.py` 检查会话失效、延迟释放、失败重试、操作朝向、边界回撤和手腕连续性。
2. `test_tracking.py` 用 367 URDF/SRDF、Mink 和两侧不同响应时间的虚拟关节比较 V5 与 V6。输入 90 Hz，关节反馈 100 Hz。到位定义为末端位置误差不超过 4 mm 且姿态误差不超过 2°，记录持续满足条件的首个采样时刻。稳态误差、运动中误差、左右到位时差和关节加加速度分别记录在 JSON 内。
3. `test_ros_loop.py` 连接真实 HTTPS 和 WebSocket 入口，运行双手跟随、手动收回、快速复位、退出后立即再进入、复位途中停用再进入，以及使能时关闭进程。底层电机和 SYNC 服务由本地 ROS 域 191 的测试节点模拟，话题后缀为 `v6_sim`。
4. `tracking.json`、`extended_tracking.json`、`loop_result.log` 和 `loop_nodes.log` 分别保存常规轨迹、大伸展轨迹、全流程结果与节点日志。

虚拟关节响应为一阶模型。模型数据适用于比较控制链路和回归测试，实机载荷、机械回差、头显无线网络及视频延时需要现场测量。

网页使能仍等待原厂复位完成和 SYNC 所有权确认。已确认复位稳定时，接管状态机在 SYNC 回执之后核对新关节反馈的速度、目标误差及保持位姿，满足条件即可进入 ARMED。普通准备模式继续使用原有稳定观察窗口。

佩戴者抬起小臂时，WebXR 提供的肘到腕方向经操作者坐标系变换后进入 IK。求解使用机器人自身肩腕轴和肘部可行圆计算臂形。抬腕时优先还原横向分量。网页显示人体前臂、保留最近肘向、抬腕姿态估计或中立臂形，可据此区分骨骼跟踪和手柄推断。固定夹爪位姿和机器人臂长会限制可实现的小臂仰角。

### 跨 Grip 的回程参考

在直伸和直收时，IK 读取人体肩到肘的横向分量，在机器人的可行肘圆上还原上臂外展量。松开换握不会重采臂形零点。前臂主要向上时仍按肘到腕方向跟踪。骨骼短时丢帧时，控制器在当前腕位重新投影同一次握持的最近骨骼观测。松开后保持实测姿态。

每只手在本次会话第一次接管时记录手柄和实测末端位姿。每次重新握持先从新的实测位姿输出。沿原行程收手时，映射按回程进度消除外伸期间的跟踪差。限位投影作用在输出侧。使能、退出、复位或切换操作者坐标系会清除旧参考。

桌面默认采用 `V6_RETURN_FRAME=clutch`。松开期间可调整握姿，收回已接管的位移和转角即可返回。固定站位且希望手柄回到房间中首次握持的绝对位姿时，可在启动环境设置 `V6_RETURN_FRAME=room`。每次启动选择一个坐标约定。

`bash run_v6.sh --simulate` 包含边界外伸 12、28、45 毫米的数值回放，并以真实 WebSocket、ROS 节点和虚拟电机复核两种回程坐标约定。测试用例记录每侧七轴、肘点、末端、接管瞬间误差和手停后的稳定时间。

`test_return.py` 从 367 实录的近伸直右臂、以及独立的左臂可行姿态出发，分别测试回收与伸出。记录行程中点滞后、手停后腕部和肘部到位时间。实录取得时 Grip 已经松开，测试使用复位目标和与实录距离相容的可达目标重建回程。镜像姿态须单独验证自碰撞。全伸附近，同一末端位姿可以对应不同的屈肘角。结果在 `return_replay.json`。

`test_arm_shape.py` 另外执行四次双臂往返、左右手共二十次重握，并在手腕位姿固定时单独改变人体肘向。结果保存在 `arm_shape.json`。首次网页使能的端到端时间和状态切换时间保存在 `first_enable.json`。原厂复位出现运动后，程序同步观察最低等待时长和连续到位时间。若尚未观察到运动，仍依次确认，以防把复位启动前的静止当成完成。
